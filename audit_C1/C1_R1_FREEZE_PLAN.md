# C1-R1 封印計画（凍結・SHA256・停止条件）

状態：REVISED DRAFT／実験禁止。**今回は評価系列を生成していないし、モデルも実行していない。** 以下は手順の設計である。

## 1. 評価系列の生成仕様

### 1.1 乱数
- Python `random.Random(92000)`。V054T（90000）、V054H（91000）、E3（98000・99000）、E2/E1 の seed とは違う値。
- 消費の順序（固定）：
  1. prefix：(ADD,0)、(ADD,1)、(SUB,0)、(SUB,1) の順。
  2. F2：(op, c) の順 → ρ の昇順 → 並べ替え番号 r = 0..3。
  3. F3：(op, c) の順 → ρ の昇順 → 平均周期 {8, 64} → 番号 r = 0..1。
- パターン（保持区間の p/q の並び）は (op, c) ごとに作り、4つの prefix と23モデルで**共通**に使う。

### 1.2 prefix
- (op, c) ごとに4本：j=0 は 'min'（`v054h.py` の `gen_prefix_suffix` と同じ最小の prefix：c=0 なら空、c=1 なら長さ1）、j=1..3 は 16 bit の乱数 (a, b) で、ripple 計算の最後の状態が c になるもの（棄却法）。
- prefix の長さがそろわない（'min' は0か1）。採点は保持区間だけなので問題はない。バッチは長さごとにまとめる。【確定案】'min' もそのまま使う。
- P1 の開始状態− には、同じ j の (op, 1−c) の prefix を使う。

### 1.3 パターン（p を 1、q を 0 と書く。長さ H=2048）
- F1 周期ブロック：(a, b) ∈ {1,2,4,8,16,32,64,128}²、(1,1) は除く。p^a q^b を繰り返し、長さ H で切る。必ず p から始める。63本。
- F2 同じ頻度の並べ替え：ρ ∈ {1/8, 1/4, 1/2, 3/4, 7/8}、n_p = ρ·H（整数）。長さ H の配列に n_p 個の1を置き、`rng.shuffle` で並べ替える。各 ρ について4本、計20本。
- F3 ラン長の乱数：ρ（上と同じ5値）× 平均周期 C ∈ {8, 64}。p のランの長さは平均 ρC、q のランの長さは平均 (1−ρ)C の幾何分布（`1 + floor(log(U)/log(1−1/μ))`、μ ≤ 1 のときは1。U は rng.random()）。p から始めて交互にランを足し、H で切る。各条件2本、計20本。
- 計103パターン/(op, c)。文脈あたり 103 × 4 prefix = 412系列。モデルあたり 4 × 412 = 1,648系列。

### 1.4 合法性の検査（生成時に assert）
- すべての保持区間の位置で、入ってくる状態 = c、出力 = y_c（独立に実装した ripple で）。
- ADD/SUB の保持区間の入力対が P(op) に属すること。

## 2. 重複と独立性の検査

### 2.1 系列レベル
- 各パターンの SHA256（'0'/'1' の文字列）を記録する。パターンどうしの重複は除き、生成順で最初のものを残す（除いた件数を記録）。
- V054H の C_mixed_probes（part3 の `evaluation_sets/v054h_dynamics/data/C_mixed_probes.jsonl`）と V054T の probes の保持パターンを、文字列のハッシュと照合する。完全に一致したものは未見の集合から除外する。長さが違う（V054H は k ≤ 1024、`hold_pairs` は k ≤ 64 でしか保存されていない）ので、完全一致は起こらない見込み。さらに、**V054H の k=64 の系列を部分文字列として含むパターン**を数えて報告する（除外はしない）。

### 2.2 規則レベル
- 周期2の厳密な交互（V054H の M_alt と同じ規則）は生成段階で除外済み（(a,b)=(1,1)）。
- M_rand（片側の入力対も含む3つの入力対から一様に選ぶ）と F2（両側の2つの入力対だけ、個数固定）は規則として近い。V054 B0 の3モデルについては「規則レベルで近い既存データがある」と記録する。主要対比を **E3 だけで計算した値**を必ず並べて報告する。
- 設計者の事前知識：R0 の作成者（この設計者と同じ）は、V054H の混合保持の結果の要約（破綻しない対だけの混合は破綻しなかった、破綻する対と破綻しない対の混合で破綻しにくくなる例があった、交互の破綻時刻は単独の破綻時刻の間にあった）を読んでいる。P1 の「回復を表すために開始状態−を使う」という設計は、この知識の影響を受けている可能性がある。独立性の制限として報告書に書く。E3 の混合入力の結果は、誰も見ていない。

## 6. 真値を開封した後に変えられない項目
- P1/B1 の式とパラメータ、文脈の除外条件、情報のある文脈の一覧、系列の集合、H、精度の方針（FP64 が主）、主指標、継続の目安、ブートストラップの方法とシード、集計スクリプト。
- 予測の精度が低いことを理由に、上のどれかを変えて再評価してはならない。開封した後に見つかったバグの修正は「事後の分析」と明記し、元の結果と並べて報告する。元の結果は消さない。

## 7. 不具合時の停止・再実行の条件

| 状況 | 対応 |
|---|---|
| 生成時の assert に失敗 | 停止。生成器を直して S3 からやり直す（真値は未開封なので問題ない）。修正の記録を残す |
| S2 の整合性テストに失敗 | 停止して研究主任に報告。FP32/FP64 の切り替えや、モデルの除外で回避することはしない |
| FP64 で非有限の値が出る（真値の開封前、固定入力で見つかった場合） | 該当するモデルを REVISE の扱いとして報告。主評価の精度は変えない |
| 実行中のクラッシュ（OOM、途中終了など） | 決定論的なコードを、同じ入力でやり直す。やり直したことを記録し、部分的な結果は捨てずに残す |
| 予算が足りなくなる見込み（各段階の前に見積もる） | **真値の開封前に**、次の順序で範囲を縮め、その時点でコミットする：(1) FP32 の感度分析をやめる、(2) B2 をやめる、(3) F3 の系列をやめる、(4) prefix を j=0,1 の2本にする。主要対比の母集団（情報のある文脈）と H は変えない。開封した後に縮めることはしない |
| 開封した後に集計スクリプトのバグが見つかった | 凍結した版の結果と修正版の結果を並べて報告する。修正版は事後の分析とする |
| 承認された上限を超える見込み | その時点で停止して報告する。自動で続けない |
